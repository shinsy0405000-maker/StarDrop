# 별똥 택배 (StarDrop)

행성의 중력을 이용해 소포를 배달지까지 휘돌려 보내는 우주 배달 퍼즐 게임입니다.
외부 게임 엔진이나 라이브러리 없이 **순수 자바(Swing)** 로 물리, 그래픽, 효과음을 모두 직접 구현했습니다.

자바 프로젝트 수행평가 작품입니다.

## 다운로드

[Releases](https://github.com/shinsy0405000-maker/StarDrop/releases/latest)에서 받을 수 있습니다.

| 파일 | 설명 |
|---|---|
| `StarDrop-windows.zip` | **윈도우용, 자바 설치 필요 없음.** 압축을 풀고 `StarDrop/StarDrop.exe` 실행 |
| `StarDrop.jar` | 자바 21 이상이 깔린 컴퓨터(윈도우, 맥, 리눅스)에서 더블클릭 또는 `java -jar StarDrop.jar` |

릴리스 파일은 GitHub Actions(`.github/workflows/release.yml`)가 Release를 발행할 때마다 자동으로 만듭니다.

## 버그 제보

게임 안에서 **버그 제보** 버튼(처음 화면 오른쪽 위, 구역 목록) 또는 **F1**을 누르면 제보 창이 열립니다.
무엇이 잘못됐는지 적고 "GitHub에 제보하기"를 누르면, 버전·구역·운영체제 정보가 채워진 [버그 제보 양식](https://github.com/shinsy0405000-maker/StarDrop/issues/new?template=bug_report.yml)이 브라우저에서 열립니다.

## 언어

**한국어 · English · 日本語 · 中文** 네 가지를 지원합니다.
처음 화면 오른쪽 위의 **언어 · Language** 버튼을 누르고 고르면 바로 바뀌고, 다음에 켤 때도 그 언어로 열립니다.
처음 켤 때는 컴퓨터 언어를 따릅니다 (네 언어가 아니면 영어).

## 후원

게임 처음 화면 오른쪽 위나 구역 목록의 **후원하기** 버튼을 누르면 후원 창이 열립니다.
5,000원 / 10,000원 / 30,000원 중에서 고르거나 직접 적을 수 있고, **최소 금액은 5,000원**입니다.
후원은 **카카오페이 송금코드**로 받습니다. 금액을 고르면 창에 QR이 나오고, 휴대폰 카메라나 카카오톡으로 찍으면 카카오페이 송금 화면이 열립니다.
게임 없이 후원하려면 → **[후원 페이지 (DONATE.md)](DONATE.md)** 에서 QR을 찍어 주세요. 저장소 위쪽 **Sponsor** 버튼으로도 갈 수 있어요.

## 직접 빌드해서 실행하기

JDK 21 이상이 필요합니다.

```
javac -encoding UTF-8 -d out src/*.java
java -cp out StarDrop
```

IntelliJ IDEA에서는 이 폴더를 열고 `src/StarDrop.java`의 `main`을 실행하면 됩니다. 나머지 파일과 `src/fonts`의 글꼴은 자동으로 같이 들어갑니다.
실행 구성의 JDK가 프로젝트 SDK와 같은지 확인하세요. 버전이 다르면 `UnsupportedClassVersionError`가 납니다.

## 게임 구성

- **태양계 9단계 × 16구역 = 144구역**: 지구 → 화성 → 금성 → 수성 → 목성 → 토성 → 천왕성 → 해왕성 → 태양 순서.
  지구 단계의 16구역은 웹 버전과 행성 위치·정답까지 똑같고, 다음 단계로 갈수록 그 행성을 닮은 천체가 더해지고 궤도가 더 휘어야 합니다. 다 끝내면 무한 배달이 이어집니다.
- **천체**: 행성(표면 5종, 고리), 공전하는 달, 블랙홀, 밀어내는 별, 웜홀
- **별 3개**: 자동 풀이기가 찾은 정답 궤도 위에 놓이므로, 별 3개를 모두 얻는 길이 반드시 있습니다.
- **기록 저장**: 구역마다 얻은 별 수가 저장되어, 구역 목록의 단계 탭에서 볼 수 있습니다. 앞 구역을 끝내야 다음 구역이 열립니다.
- **소리**: 배경음, 추진음, 효과음을 음원 파일 없이 코드로 직접 계산해 만듭니다.

## 핵심 원리

**중력 계산** (`GravityBody.pull`): 만유인력 공식에 따라 가속도 = 질량 / 거리² 를 천체 방향으로 더합니다.

**운동 갱신** (`Ship.step`): 0.01초마다 가속도 → 속도 → 위치 순으로 갱신합니다.

**자동 풀이기** (`Solver.solve`): 각도 720개(0.5도 간격) × 세기 12단계를 모두 시뮬레이션하는 완전 탐색입니다.
도착한 궤도 중 각도와 세기가 조금 어긋나도 성공하는 것만 정답으로 채택해, 사람이 실제로 맞힐 수 있는 구역만 만듭니다.

**웹과 똑같은 구역** (`Mulberry32`, `JsMath`): 웹 버전과 같은 난수 생성기와, 브라우저와 소수점 끝자리까지 같은 수학 함수를 써서
같은 씨앗이면 웹과 완전히 같은 구역이 만들어집니다.

## 객체 지향 설계

| 개념 | 적용 |
|---|---|
| 캡슐화 | 모든 필드는 `private`, getter로만 읽기. 반지름이 0 이하이면 생성자에서 예외 |
| 인터페이스 | `CelestialBody`: 행성, 블랙홀, 밀어내는 별, 달이 구현. 물리 계산은 종류를 모른 채 `pull()`만 호출 |
| 인터페이스 | `Drawable`: 화면에 그릴 대상을 반복문 하나로 그림 |
| 상속 | `GravityBody`(추상 클래스) ← `Planet`, `BlackHole`, `Repulsor` |
| 상속 | `Widget`(추상 클래스) ← `Button`, `LevelTile`: 화면 위의 클릭할 수 있는 요소 |
| 상속 | `GameState` ← `WorldPainter` ← `ScreenPainter` ← `StarDrop`: 게임 본체를 상태, 우주 그리기, UI 그리기, 진행·입력 네 층으로 나눔 |
| 상속 | `MouseAdapter`, `KeyAdapter`를 상속해 필요한 메서드만 재정의 |

- **구역 생성을 웹과 한 줄씩 똑같이**: `java.util.Random` 대신 웹의 난수 생성기(mulberry32)를 옮긴 `Mulberry32`를 쓰고,

  천체를 더하는 순서도 웹과 같게(행성·블랙홀·밀어내는 별 → 달) 바꿈
- 확인: 웹 코드를 node로 돌린 결과와 비교해 16구역 + 무한 배달 8개의 출발점, 천체 위치, 정답 각도·세기, 별 위치, 행성 종류·색이 **소수점 끝자리까지 모두 같음**
- 행성 그림(`drawPlanetSprite`), 배경 성운과 별(빛을 더하는 방식, `AdditiveComposite`), 반짝이는 별도 웹과 같은 난수 순서로 그려서 같은 모양이 나옴
- **태양계 9단계 × 16구역 = 144구역** (`Campaign`): 지구(= 웹의 16구역) → 화성(달 +1) → 금성(밀어내는 별 +1) → 수성(블랙홀 +1) → 목성(행성·달 +1)
  → 토성(달·웜홀) → 천왕성 → 해왕성 → 태양(전부 +1). 단계마다 최소 휨 +0.06, 조준 점선 −10
- 144구역 모두 풀이기로 검증하고 "처음 성공하는 시도 번호"를 미리 구해 둠 → 어느 구역이든 바로 열림
- 구역 목록에 단계 탭 추가(단계별 모은 별), HUD 운송장에 "단계" 칸, 단계 마지막 구역 영수증에 "다음 단계: 화성" 버튼, 단계 첫 구역 안내 문구
- 기록 저장 이름을 `progress2`로 바꿈 (예전 5구역 기록은 다른 구역이라 섞이지 않게)
- **웹과 같은 글꼴**: Black Han Sans(제목), IBM Plex Sans KR(본문, 400/500/700), IBM Plex Mono(숫자)를 `src/fonts`에 넣고 읽음.
  글꼴에 없는 글자(고정폭 글꼴의 한글 등)는 브라우저처럼 다른 글꼴로 대신 그림
- **화면 배치를 CSS 숫자 그대로**: 크롬으로 웹을 띄워 각 요소의 위치·크기를 재고 같게 맞춤 (운송장 높이, 도구 버튼이 운송장 높이로 늘어나는 것, 안내 상자 폭 62글자, 구역 목록·영수증 간격 등).
  한글은 글자 사이에서도 줄을 바꾸고, 마지막 줄에 한 덩어리만 남지 않게(text-wrap: pretty) 함
- 영수증이 뜨면 웹처럼 HUD 버튼도 어두운 판 아래에 깔리고 눌리지 않음. 제목 빛 번짐을 가우스 블러(60px)로 바꿈
- 버그 수정: 운송장 칸막이·영수증 아래 점선이 글자 색으로 그려지던 것

### 2026-11-23 — 캐시 정리와 최적화
- 여기저기 흩어져 있던 "미리 그려 두는 그림" 코드를 두 파일로 모음
  - `CachedImage`: 그림 한 장 + 열쇠(창 크기, 구역 등). 열쇠가 같으면 저장한 그림을 그대로 쓰고, 바뀔 때만 다시 그림
  - `ImageCache`: 빛 번짐 그림(색마다 한 장), 창 크기 그림 만들기/붙이기 도우미
  - 배경, 행성 축소 그림이 `CachedImage`를 쓰도록 바꿈. 배경은 이제 윈도우 배율(125%, 150%)이 바뀌어도 다시 그림
- 처음 화면: 화면 전체 그라데이션과 큰 제목 글자를 매 프레임 새로 그리던 것을 한 장으로 캐시 → 한 프레임 15.0ms → 6.7ms (1920×1080)
- 자동 풀이기: 720개 각도를 CPU 코어 여러 개에 나눠 동시에 계산하고, 각도 순서대로 다시 모아서 정답은 전과 똑같음. 튼튼한지 검사할 때 한 번 실패하면 바로 멈춤 → 구역 8개 만드는 시간 4.2초 → 2.3초 (2코어 기준, 코어가 많을수록 더 빨라짐)
- 확인: 5개 구역과 무한 배달 구역의 정답이 전과 같음, 비행 결과 별 3개 배달 성공, 방향키 시험 값 같음, 화면은 처음 화면만 색이 최대 2/255 차이(눈으로 구분 안 됨)
